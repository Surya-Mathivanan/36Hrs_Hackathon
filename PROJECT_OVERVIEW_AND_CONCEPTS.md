# 🌍 Campus Carbon Footprint Analyzer - Overview & Concepts

This document explains the core concepts, purpose, calculations, and operational flow of the Campus Carbon Footprint Analyzer built for KIT.

---

## 1. 🎯 Purpose & Vision

The primary purpose of this project is to **measure, visualize, and reduce the carbon emissions** generated by the campus. 
It aligns directly with **United Nations Sustainable Development Goal (SDG) 13: Climate Action**.

Institutions like universities and colleges have large, complex carbon footprints. They consume massive amounts of electricity, operate bus fleets, run large canteens, and generate significant waste. Furthermore, the sheer concentration of humans (students + staff) on campus has an inherent environmental impact.

**By migrating from a monolithic Flask application to a modern Django + React architecture**, this platform achieves:
- **Better scalability** to handle years of daily data records.
- **Improved user experience** with dynamic React charting.
- **Stronger API isolation** ensuring raw data can be accessed securely across platforms.

---

## 2. 🧠 Main Concept: Scopes of Emission

The project tracks environmental impact based on the standard Greenhouse Gas (GHG) Protocol, categorized into actionable campus sources:

1. **Scope 1 (Direct Emissions)**
   - **Bus Diesel:** Emissions from combustion in campus-owned transport vehicles.
   - **Canteen LPG:** Emissions from burning Liquefied Petroleum Gas for cooking in campus cafeterias.
2. **Scope 2 (Indirect - Owned)**
   - **Electricity:** Emissions released indirectly through the purchase of grid electricity (power plants burning coal/gas to generate the electricity used on campus).
3. **Scope 3 (Indirect - Value Chain) & Others**
   - **Waste to Landfill:** Methane (a potent GHG) released as organic campus waste decomposes in landfills.
4. **CORE FEATURE: Human CO₂ Emissions**
   - The platform uniquely accounts for the direct metabolic output (respiration) of the campus population. A heavy concentration of humans in a small area generates indirect operational loads and direct biological CO₂.

## 3. 🧮 How We Calculate: The Math

All calculations are mapped to **Emission Factors**. An emission factor is a representative value that relates the quantity of a pollutant released to the atmosphere with an activity associated with the release of that pollutant.

The formula across the platform is simple but industry-standard:
**`Emissions (Tonnes CO₂e) = (Raw Consumption × Emission Factor) ÷ 1000`**

### Active Emission Factors Used in the System:

| Source Type | Measuring Unit | Emission Factor (`factor`) | Resulting Unit |
| :--- | :--- | :--- | :--- |
| **Electricity** | kWh (Kilowatt-hours) | `0.708` | kg CO₂e / kWh |
| **Bus Diesel** | Liters | `2.68` | kg CO₂e / Liter |
| **Canteen LPG** | kg (Kilograms) | `2.93` | kg CO₂e / kg |
| **Waste (Landfill)** | kg (Kilograms) | `1.25` | kg CO₂e / kg |
| **Human Population** | Persons (Students+Staff) | `1.0` | kg CO₂e / person / day |

**Example Calculation (Electricity):**
If the campus uses `120,000 kWh` of electricity in a month:
1. `120,000 × 0.708 = 84,960 kg CO₂e`
2. `84,960 ÷ 1000 = 84.96 Tonnes CO₂e`

The backend Database stores the `raw_value` (e.g., 120000). The calculations are performed dynamically by the Django API serializers and views.

## 4. 📝 How We Add Input Data

Data input is restricted to **Authenticated Administrators** (using JWT tokens). Data can be entered through the `/data-input` page on the React frontend.

There are three main ways data flows into the system:

### A. Manual Activity Data Entry
For daily/monthly utility bills. The admin selects the date, chooses the `Source Type` (e.g., Electricity), and types the `Raw Value` (e.g., 5000). The form automatically knows the correct unit (kWh) and securely POSTs to the Django `/api/data/` endpoint.

### B. Campus Population Data (Human Input)
This is a dedicated module. The admin selects the date and inputs the `Student Count` and `Staff Count`.
- The API creates or updates the record for that specific date.
- It calculates the "This Day Emissions" based on `(Students + Staff) * 1.0 kg`.
- It dynamically recalculates cumulative total emissions and average daily populations across the entire database lifespan.

### C. CSV Bulk Upload
To prevent data-entry fatigue when onboarding historical data (e.g., uploading the last 5 years of electricity bills). 
- Admins can drag-and-drop a `.csv` file. 
- The format must strictly be: `date, source_type, raw_value, unit`.
- The React frontend validates the CSV headers and data types.
- A single JSON payload containing an array of records is sent to `/api/upload_csv/`.
- Django utilizes `bulk_create` to insert thousands of rows into PostgreSQL instantly.

## 5. 📊 How It Works: The Dashboard & API

The core of the value provided is the **Analytical Dashboard**, available publicly at `/`.

When a visitor loads the Dashboard:
1. **React State:** The frontend defines a date range (defaulting to "Last 365 Days").
2. **API Call:** Axios fetches `http://localhost:8000/api/dashboard/?start_date=X&end_date=Y`.
3. **Django Aggregation:** The Django backend queries PostgreSQL. It uses database-level aggregates (`Sum`, `Avg`, `Count`) to group data by days, weeks, months, and years.
4. **Data Delivery:** Django returns a structured JSON containing KPIs, daily trends, weekly comparisons, and source breakdowns.
5. **Chart.js Visualization:** React takes this JSON and renders dynamic Line, Bar, and Doughnut charts.

---

## 6. 💡 The Recommendation Engine

The system doesn't just show data; it provides actionable advice. 
When the Dashboard loads, it calls `/api/recommendations/`.

**How it works:**
1. The Django view queries the database to find the **Biggest Polluter** (e.g., Electricity).
2. Based *only* on what is mathematically the largest source of emissions for that specific campus, it dynamically serves a tailored "High Priority" recommendation package.
3. If `bus_diesel` is the highest, it focuses on EV transition and route optimization. If `electricity` is highest, it focuses on LED refitting, smart sensors, and auditing.
4. It also provides "Quick Wins" (low cost, immediate impact) and general strategic advice for setting up "Green Teams."

---

## 7. 🔒 System Security

- **Authentication:** Data input requires a JWT (JSON Web Token). When the admin logs in via React, Django verifies the bcrypt-hashed password in PostgreSQL, issues an Access Token (valid for 24h) and a Refresh Token (valid for 7d).
- **Protection:** All POST endpoints in Django (`api/views.py`) are wrapped in `@permission_classes([IsAuthenticated])`.
- **Validation:** Both React (frontend) and Django REST Framework (backend via `serializers.py`) prevent negative numbers and invalid source types from entering the database.
